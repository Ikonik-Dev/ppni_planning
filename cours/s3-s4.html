🔌 Séquence 3.1 — Qu'est-ce qu'un réseau ?

Durée : 1h30 — Vocabulaire + schéma + manipulation

10% — Théorie

Vocabulaire réseau essentiel

  • Adresse IP : identifiant unique d'un appareil (ex: 192.168.1.1)
  • DNS : annuaire qui traduit google.com → 142.250.75.78
  • Protocole : règles communes pour se comprendre
  • Paquet : fragment de donnée envoyé sur le réseau
  • Client / Serveur : celui qui demande / celui qui répond
  • Routeur : aiguilleur qui choisit le chemin des paquets
⏱ 25 min
70% — Pratique

Schéma du réseau + observer sa propre IP

  • Dessiner au tableau : ordinateur → box → routeur → Internet → serveur
  • Terminal : ipconfig (Windows) ou ifconfig (Mac/Linux) pour voir son IP locale
  • Navigateur : aller sur whatismyip.com pour voir son IP publique
  • Comparer : IP locale ≠ IP publique — pourquoi ?
⏱ 45 min
20% — Collaboration

Discussion : ce qu'on croyait savoir

  • Qui a déjà vu une adresse IP ? Dans quel contexte ?
  • Qu'est-ce qui se passe selon vous quand vous tapez une URL ?
  • Construction collective du schéma réseau
⏱ 20 min
10h30 – 12h30 Protocoles HTTP/HTTPS, DNS, TCP/IP — la langue d'Internet

📡 Séquence 3.2 — Protocoles fondamentaux

Durée : 2h — 3 protocoles + DevTools

💡 Idée clé : Un protocole, c'est une langue commune. HTTP, c'est la langue que ton navigateur et le serveur utilisent pour se parler. DNS, c'est l'annuaire qui traduit les noms en adresses. TLS/HTTPS, c'est l'enveloppe cachetée qui protège ce qu'ils se disent.
10% — Théorie

HTTP, DNS, TCP/IP — comment ça s'articule

  • TCP/IP : protocole de transport — découpe et reconstitue les paquets
  • DNS : requête → résolution → IP du serveur
  • HTTP : GET (demander) / POST (envoyer) / codes réponse
  • HTTPS = HTTP + TLS : toutes les données sont chiffrées
  • Codes HTTP importants : 200 (OK), 301 (redirection), 404 (non trouvé), 500 (erreur serveur)
⏱ 25 min
70% — Pratique

Inspecter le trafic avec DevTools

  • Ouvrir Chrome/Firefox → F12 → onglet "Réseau"
  • Aller sur example.com → observer les requêtes
  • Identifier : méthode (GET), statut (200), type (document, js, css, img)
  • Comparer http://neverssl.com (HTTP) vs https://github.com (HTTPS)
  • Voir le certificat TLS d'un site (cliquer sur le cadenas)
⏱ 70 min
20% — Collaboration

Discussion : HTTP vs HTTPS — pourquoi ça compte

  • Scénario : login sur un site HTTP — que voit un attaquant ?
  • Pourquoi les navigateurs affichent un avertissement sur HTTP ?
  • Vote : qui avait déjà fait attention au cadenas ?

13h20 – 15h00 Ports, pare-feu, Wi-Fi public — les portes du réseau

🚪 Séquence 3.3 — Ports et sécurité réseau

Durée : 1h40 — Table des ports + scénario Wi-Fi

10% — Théorie

Ports et pare-feu

  • Port 22 — SSH (accès distant sécurisé)
  • Port 80 — HTTP
  • Port 443 — HTTPS
  • Port 25 / 587 — SMTP (e-mail)
  • Port 3389 — RDP (Bureau à distance Windows)
  • Pare-feu : filtre les connexions selon port + IP + règles
  • URL complète : https://site.com:443/page?q=test
⏱ 20 min
70% — Pratique

Table des ports + analyse d'URL

  • Compléter une fiche : 10 ports à associer à leurs protocoles
  • Décomposer 5 URL en : schéma / hôte / port (implicite) / chemin / paramètres
  • Trouver le port d'écoute d'un service local : netstat -an | findstr LISTEN
⏱ 65 min
20% — Collaboration

Scénario : Wi-Fi public au café

  • Mise en situation : tu travailles dans un café, Wi-Fi ouvert
  • Discussion : quels sont les risques ? (sniffing, man-in-the-middle)
  • Solutions : VPN, sites HTTPS only, ne pas saisir de mots de passe
⏱ 15 min
15h00 – 17h00 TP réseau — explorer son réseau avec le terminal

🖥️ Séquence 3.4 — TP terminal réseau

Durée : 2h — 4 commandes réseau essentielles

🛠️ Objectif : Utiliser 4 commandes réseau dans le terminal pour observer le réseau en temps réel. Pas de magie — juste des outils que tout technicien numérique doit connaître.
70% — Pratique

4 commandes à maîtriser

  • ping google.com — tester la connectivité + latence
  • tracert google.com (Windows) / traceroute (Mac/Linux) — tracer le chemin des paquets
  • nslookup github.com — résolution DNS manuelle
  • ipconfig /all (Windows) — voir toute la configuration réseau
  • Observer la différence de latence : ping 8.8.8.8 vs ping 192.168.1.1
⏱ 80 min
20% — Collaboration

Comparer les résultats en binôme

  • Chaque binôme trace le chemin vers un site différent
  • Combien de sauts entre votre machine et le serveur ?
  • Présentation de 2 min : "Notre chemin vers [site]"
⏱ 25 min
10% — Théorie

Lire les résultats

  • TTL (Time To Live) : nombre de sauts restants avant abandon du paquet
  • ms (millisecondes) : latence — < 20ms = excellente, > 200ms = lent
  • * * * = nœud qui ne répond pas au ping (pare-feu)
⏱ 15 min

🌍 Séquence 3.6 — Du réseau au Web

Durée : 2h

10% — Théorie

Les 3 langages du Web

  • HTML — le squelette (structure et contenu)
  • CSS — l'habit (couleurs, mise en page, animations)
  • JavaScript — les muscles (interactions, dynamisme)
  • Le navigateur = machine qui lit ces 3 fichiers et affiche le résultat
⏱ 15 min
70% — Pratique

"Afficher la source" — décortiquer une vraie page

  • Sur n'importe quel site : clic droit → "Afficher la source" (Ctrl+U)
  • Identifier : <html>, <head>, <body>, <h1>, <a href>
  • DevTools → onglet "Éléments" : survoler le DOM, voir les styles CSS associés
  • Modifier une couleur ou un texte en direct dans DevTools (non permanent)
⏱ 70 min
20% — Collaboration

  • Réponse surprenante : plusieurs milliers (CSS + JS + HTML)

🏛️ Séquence 4.1 — HTML : le squelette

Durée : 1h30

10% — Théorie

Structure HTML minimale

  • <!DOCTYPE html> — déclaration du type de fichier
  • <html lang="fr"> — racine du document
  • <head> — métadonnées (title, charset, CSS)
  • <body> — contenu visible
  • Balises sémantiques : <nav>, <main>, <section>, <article>, <footer>
  • Balises de contenu : <h1>-<h6>, <p>, <a>, <img>, <ul>, <li>
⏱ 20 min

  • Créer un fichier index.html dans un nouveau dossier

🎨 Séquence 4.2 — CSS : habiller la structure

Durée : 2h — Théorie + éditeur live

💡 CSS, c'est quoi ? Une règle CSS dit : "Tous les éléments h1 doivent être bleus, en police Inter, taille 32px, avec 20px d'espace en dessous." CSS donne un style à ta structure HTML.
10% — Théorie

Sélecteurs et box model

  • Sélecteur élément : h1 { color: red; }
  • Sélecteur classe : .card { padding: 16px; }
  • Sélecteur ID : #nav { background: #fff; }
  • Box model : content → padding → border → margin (de l'intérieur vers l'extérieur)
  • Propriétés essentielles : color, background, font-size, font-family, border-radius, box-shadow
⏱ 20 min

📱 Séquence 4.3 — Flexbox et responsive

Durée : 1h40

10% — Théorie

Flexbox en 5 minutes

  • display: flex — active flexbox sur un conteneur
  • flex-direction : row (horizontal) ou column (vertical)
  • justify-content : alignement sur l'axe principal
  • align-items : alignement sur l'axe secondaire
  • gap : espace entre les éléments flexibles
  • Media queries : @media (max-width: 768px) { ... }
⏱ 15 min
70% — Pratique

Navbar responsive dans l'éditeur live

  • Exercice 4 dans l'éditeur : navbar horizontale en desktop

  • Appliquer sur sa page index.html locale

15h00 – 17h00 JavaScript — interactions utilisateur et manipulation du DOM

⚡ Séquence 4.4 — JavaScript : donner vie à la page

Durée : 2h

💡 JS, c'est quoi concrètement ? Quand tu cliques sur un bouton et quelque chose se passe sans recharger la page — c'est JavaScript. Quand un menu s'ouvre, qu'un formulaire se valide, qu'une notification apparaît — c'est JS. C'est le langage vivant du Web.
10% — Théorie

JS essentiel — 5 concepts

  • Variable : const nom = "Alice";
  • Fonction : function direBonjour() { ... }
  • Sélectionner un élément : document.getElementById("btn")
  • Modifier le contenu : element.textContent = "Nouveau texte"
  • Écouter un clic : btn.addEventListener("click", fonction)
⏱ 20 min
70% — Pratique

Exercice 5 — Bouton interactif

  • Intégrer cet élément dans sa page index.html locale

🚀 Séquence 4.6 — Mise en ligne sur GitHub Pages

Durée : 2h — Déploiement pas à pas

70% — Pratique

Du fichier local à l'URL publique

  • Créer un nouveau repo GitHub : ppni-landing-page (public)
  • Committer et pusher les fichiers HTML/CSS/JS via GitHub Desktop
  • Settings → Pages → Source : main branch → / (root)
  • Attendre 2-3 minutes → URL générée : https://username.github.io/ppni-landing-page/
  • Vérifier sur mobile et sur un autre ordinateur que la page s'affiche
  • Envoyer l'URL au formateur avant 12h30
⏱ 80 min
20% — Collaboration

Visiter les pages des camarades

  • Chaque stagiaire partage son URL dans le chat de groupe
  • Chacun visite au moins 2 pages de camarades depuis son téléphone
  • Retour sur la table : "J'ai aimé le…" / "Une idée d'amélioration…"
⏱ 25 min
10% — Théorie

Comment GitHub Pages fonctionne

  • GitHub Pages = serveur statique gratuit (pas de backend, pas de base de données)
  • À chaque push sur main : redéploiement automatique en ~1 min
  • HTTPS activé automatiquement (certificat TLS gratuit Let's Encrypt)
