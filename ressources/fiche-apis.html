📦 JSON — JavaScript Object Notation

JSON, c'est quoi ? Un format texte pour échanger des données structurées. Lisible par les humains, parsable par toutes les langues de programmation. C'est la "monnaie commune" des APIs web.

Les 6 types de données JSON

String Texte entre guillemets doubles "Bonjour le monde"
Number Entier ou décimal, sans guillemets 42 3.14
Boolean Vrai ou faux, minuscules true false
Null Absence de valeur explicite null
Array Liste ordonnée entre crochets [1, "a", true]
Object Paires clé:valeur entre accolades {"id": 1, "nom": "Alice"}

Exemple JSON complet

// Réponse typique d'une API REST (GET /users/1) { "id": 1, "name": "Alice Dupont", "email": "alice@example.com", "actif": true, "score": null, "tags": ["dev", "front"], "adresse": { "ville": "Paris", "cp": "75001" } }
Opération JavaScript Résultat
Parse JSON.parse('{"id":1}') Chaîne JSON → Objet JS manipulable
Stringify JSON.stringify({id: 1}) Objet JS → Chaîne JSON à envoyer
Accès obj.adresse.ville Lecture d'un champ imbriqué
Accès array obj.tags[0] Premier élément du tableau → "dev"

🔀 Méthodes HTTP (verbes REST)

Méthode Action Exemple Idempotente ? Body ?
GET Lire une ressource (sans modifier) GET /users/1 ✅ Oui Non
POST Créer une nouvelle ressource POST /users ❌ Non JSON ✅
PUT Remplacer une ressource entière PUT /users/1 ✅ Oui JSON ✅
PATCH Modifier partiellement une ressource PATCH /users/1 ✅ Oui JSON ✅
DELETE Supprimer une ressource DELETE /users/1 ✅ Oui Non
Idempotent = appeler la méthode 1 fois ou 10 fois donne le même résultat. GET /users/1 retourne toujours le même utilisateur. DELETE /users/1 supprime l'utilisateur — rappeler DELETE sur un utilisateur déjà supprimé retourne toujours 404 (même résultat). POST crée à chaque appel une nouvelle ressource → non idempotent.

🔢 Codes de statut HTTP

2xx — Succès

CodeNomQuand ?
200 OK GET/PUT/PATCH réussi avec contenu retourné
201 Created POST réussi — nouvelle ressource créée (header Location inclus)
204 No Content DELETE réussi — aucun contenu à retourner

3xx — Redirections

CodeNomQuand ?
301 Moved Permanently Ressource déplacée définitivement vers une nouvelle URL
304 Not Modified Ressource inchangée depuis le dernier accès (cache valide)

4xx — Erreurs client

CodeNomQuand ?
400 Bad Request Requête mal formée — JSON invalide, paramètre manquant
401 Unauthorized Non authentifié — il faut fournir des credentials
403 Forbidden Authentifié mais pas autorisé à accéder à cette ressource
404 Not Found Ressource introuvable à cette URL
422 Unprocessable Entity JSON valide mais données sémantiquement incorrectes (email invalide…)
429 Too Many Requests Rate limit dépassé — attendre avant de renvoyer

5xx — Erreurs serveur

CodeNomQuand ?
500 Internal Server Error Le serveur a planté — bug côté API
502 Bad Gateway Le proxy/reverse-proxy n'a pas reçu de réponse valide
503 Service Unavailable Serveur en maintenance ou surchargé

📋 Headers HTTP courants

HeaderDirectionRôle & exemple
Content-Type Requête & Réponse Format du body : Content-Type: application/json
Accept Requête Format attendu en réponse : Accept: application/json
Authorization Requête Credentials : Authorization: Bearer eyJhbGci...
X-API-Key Requête Clé API : X-API-Key: abc123 (dépend de l'API)
Cache-Control Requête & Réponse Contrôle du cache : Cache-Control: no-cache
X-RateLimit-Remaining Réponse Nombre de requêtes restantes dans la fenêtre de temps

⚡ cURL — Cheat Sheet

cURL = outil ligne de commande pour envoyer des requêtes HTTP depuis le terminal. Disponible sur Windows (PowerShell), macOS et Linux.
# GET simple curl https://jsonplaceholder.typicode.com/posts/1 # GET avec affichage des headers de réponse curl -I https://jsonplaceholder.typicode.com/posts/1 # GET avec headers de requête personnalisés curl -H "Accept: application/json" https://api.example.com/data # POST avec body JSON curl -X POST https://jsonplaceholder.typicode.com/posts \ -H "Content-Type: application/json" \ -d '{"title": "Mon titre", "body": "Mon texte", "userId": 1}' # PATCH — modifier partiellement curl -X PATCH https://jsonplaceholder.typicode.com/posts/1 \ -H "Content-Type: application/json" \ -d '{"title": "Nouveau titre"}' # DELETE curl -X DELETE https://jsonplaceholder.typicode.com/posts/1 # Avec Bearer token curl -H "Authorization: Bearer MON_TOKEN" https://api.example.com/me # Voir code de statut seulement curl -o /dev/null -s -w "%{http_code}" https://jsonplaceholder.typicode.com/posts/1
Option cURLSignification
-X METHODSpécifier la méthode HTTP (GET par défaut)
-H "Header: value"Ajouter un header de requête
-d 'data'Body de la requête
-I ou --headAfficher seulement les headers de réponse
-vMode verbose — voir toute la requête/réponse
-sMode silencieux — masquer la progression
-o fichierSauvegarder la réponse dans un fichier

🛠️ Postman — Quick Tips

FonctionnalitéComment faire
Nouvelle requête Ctrl+N → choisir méthode → saisir URL → Send
Ajouter un header Onglet Headers → Key: Content-Type → Value: application/json
Body JSON Onglet Body → sélectionner "raw" → choisir "JSON" → saisir le JSON
Authentification Bearer Onglet Auth → Type: "Bearer Token" → coller le token
Variables d'environnement Bouton "Environments" → New → ajouter BASE_URL = URL de l'API → utiliser {{BASE_URL}} dans les requêtes
Exporter une collection Clic droit sur la collection → Export → Format v2.1 → Save
Importer une collection Import (coin haut gauche) → glisser le fichier JSON de la collection
Voir les cookies Onglet Cookies dans la réponse
Bonne pratique sécurité : Ne jamais hard-coder les tokens directement dans les URLs ou les sauvegarder dans des collections partagées. Utiliser les variables d'environnement Postman qui sont stockées localement et non exportées par défaut.
