🏗️ Le modèle réseau simplifié (4 couches)

Internet repose sur un modèle en couches. Chaque couche a un rôle précis et communique avec les couches adjacentes. Voici une version simplifiée (modèle TCP/IP) :

4 Application HTTP, HTTPS, DNS, SMTP, SSH, FTP
3 Transport TCP (fiable), UDP (rapide)
2 Internet IP (adressage), ICMP (ping)
1 Accès réseau Ethernet, Wi-Fi, câble physique
À retenir : Quand tu envoies un e-mail, il passe par toutes les couches. L'application (couche 4) construit le message, TCP (couche 3) le découpe en paquets, IP (couche 2) adresse chaque paquet, et le câble ou Wi-Fi (couche 1) le transporte physiquement.

🔢 Adressage IP

Concept Explication Exemple
IPv4 Adresse sur 32 bits (4 octets). ~4,3 milliards d'adresses possible. Format : 4 nombres séparés par des points, chacun entre 0 et 255. 192.168.1.42
IPv6 Adresse sur 128 bits. Nécéssaire car IPv4 est épuisé. Format : 8 groupes de 4 chiffres hexadécimaux. 2001:0db8::1
IP privée Utilisée uniquement sur un réseau local (LAN). Non routable sur Internet. Plages réservées : 10.x.x.x, 172.16-31.x.x, 192.168.x.x 192.168.1.1 à 192.168.1.254
IP publique Adresse visible sur Internet. Attribuée par ton FAI (Orange, SFR…). Partagée entre tous les appareils de ton réseau via le NAT. 82.123.45.67
Masque Définit quelle partie de l'IP identifie le réseau (vs l'hôte). Ex : /24 = 255.255.255.0 → 256 adresses dans le réseau. 255.255.255.0 (/24)
Passerelle L'adresse IP du routeur. C'est la "sortie" du réseau local vers Internet. Souvent la première IP du réseau. 192.168.1.1
TCP vs UDP : TCP (Transmission Control Protocol) = livraison garantie, avec accusé de réception. Utilisé pour le web, les e-mails, SSH. Plus lent mais fiable. UDP (User Datagram Protocol) = rapide mais sans garantie. Utilisé pour le streaming vidéo, les jeux en ligne, le DNS.

🌍 HTTP / HTTPS — Le protocole du Web

HTTP = HyperText Transfer Protocol. La "langue" que ton navigateur et le serveur parlent. HTTPS = HTTP + TLS (chiffrement). Toutes les données sont chiffrées de bout en bout. Sur un site HTTPS, même ton FAI ne peut pas lire ce que tu envoies.

Codes de réponse HTTP essentiels

Code Signification Exemple d'utilisation
200 OK Succès — la ressource est retournée Page web chargée normalement
201 Created Ressource créée avec succès (souvent après un POST) Compte créé sur un site
301 Moved Permanently Redirection permanente vers une nouvelle URL http:// redirigé vers https://
304 Not Modified Ressource en cache, pas besoin de retélécharger Image déjà en cache navigateur
400 Bad Request Requête malformée — le serveur ne comprend pas Paramètre manquant dans un formulaire
401 Unauthorized Authentification requise — non identifié Accès à une API sans token
403 Forbidden Identifié mais pas les droits nécessaires Accéder à un fichier protégé
404 Not Found Ressource introuvable à cette URL Page supprimée ou URL mal tapée
500 Internal Server Error Le serveur a planté à cause d'une erreur interne Bug dans le code côté serveur
503 Service Unavailable Serveur temporairement indisponible (surcharge, maintenance) Site en maintenance
Méthodes HTTP fréquentes : GET = demander une ressource (ne modifie rien) · POST = envoyer des données (formulaires, login) · PUT/PATCH = modifier une ressource · DELETE = supprimer une ressource

🚪 Ports courants

Un port est un numéro entre 0 et 65535 qui identifie un service sur un serveur. L'adresse IP identifie la machine, le port identifie l'application.

Port Protocole Usage
20/21 FTP Transfert de fichiers (non chiffré)
22 SSH Connexion distante sécurisée au terminal d'un serveur
25 / 587 SMTP Envoi d'e-mails (25 = serveur à serveur, 587 = client)
53 DNS Résolution de noms de domaine (UDP et TCP)
80 HTTP Web non chiffré — navigateur vers serveur web
110 / 993 POP3 / IMAPS Réception d'e-mails (993 = IMAP sécurisé)
143 / 993 IMAP Consultation d'e-mails sur serveur
443 HTTPS Web chiffré (TLS) — le standard actuel pour tous les sites
3389 RDP Bureau à distance Windows (Remote Desktop Protocol)
8080 / 8443 HTTP-alt Ports alternatifs pour serveurs HTTP/HTTPS de développement

💻 Commandes réseau essentielles (Windows)

📡 ping — Tester la connectivité

ping google.com # Envoie 4 paquets ICMP, mesure la latence Réponse de 142.250.75.78 : octets=32 temps=12 ms TTL=113 ping 8.8.8.8 -n 10 # Envoie 10 paquets (au lieu de 4)

🗺️ tracert — Tracer le chemin des paquets

tracert google.com # Affiche chaque routeur traversé et sa latence 1 <1 ms 192.168.1.1 [Box Internet] 2 10 ms 10.x.x.x [FAI] 3 15 ms 142.250.x.x [Google]

🔍 nslookup — Résolution DNS manuelle

nslookup github.com Nom : github.com Adresse : 140.82.121.4 nslookup github.com 1.1.1.1 # Utilise le DNS Cloudflare (1.1.1.1) pour la résolution

⚙️ ipconfig — Configuration réseau

ipconfig # Affiche les IPs de toutes les interfaces ipconfig /all # Version complète : MAC, DHCP, DNS, passerelle ipconfig /flushdns # Vide le cache DNS (utile si un site ne se charge plus)

🔌 netstat — Connexions actives

netstat -an # Affiche toutes les connexions et ports en écoute netstat -an | findstr :443 # Filtrer : voir les connexions HTTPS actives

🔒 Sécurité réseau — Points clés

Menace / Concept Explication Protection
Man-in-the-Middle Un attaquant s'intercale entre toi et le serveur pour lire/modifier le trafic. Fréquent sur Wi-Fi public non sécurisé. Utiliser HTTPS uniquement · Activer un VPN
DNS Spoofing Falsifier la réponse DNS pour rediriger vers un faux site (ex: faux site bancaire). Utiliser DNS over HTTPS (DoH) · DNS de confiance (1.1.1.1)
Port Scanning Scanner les ports ouverts d'une machine pour trouver des services vulnérables. Outil courant : nmap. Fermer les ports inutiles · Pare-feu bien configuré
Pare-feu Filtre le trafic entrant et sortant selon des règles (port, IP source, protocole). Peut être logiciel (Windows Defender) ou matériel (routeur). Activer le pare-feu Windows · Règles strictes en entreprise
VPN Tunnel chiffré entre ton appareil et un serveur VPN. Masque ton IP réelle et chiffre tout ton trafic, même sur Wi-Fi public. Utiliser un VPN de confiance sur réseaux publics
